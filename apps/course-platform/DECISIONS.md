# 技术决策

## C-001：复用业务，新增独立Web应用

基于main已验证提交创建独立工作树，不覆盖原668条未提交状态。Web层通过固定子进程适配器复用integrations/graduation；P1/P2/P3业务代码不改。新任务状态只进入本应用.runtime；不操作原服务、容器、数据库或账本。

## C-002：本机单用户、零新增依赖

HTTP/API、SQLite任务索引和后台队列采用Python标准库；前端使用原生HTML/CSS/JavaScript，无CDN、构建链或新包。业务子进程使用各项目已有.venv。该方案可离线启动，适合作为课设基线；远程部署、真实身份与多租户需要独立设计，标准库服务器不作为生产HTTP服务。

## C-003：工作流与HTTP进程分离

既有Runtime安装禁止网络的audit hook，不能直接导入HTTP进程。Web服务不加载模型或图模块，通过白名单解释器和脚本运行worker；子进程环境只传必要系统变量，关闭trace。后台串行执行，HTTP请求立即返回job；超时只终止本应用创建的进程树。

## C-004：先完成闭环，不伪装开放问答

用户可命名任务、描述比较问题、查看证据并作出两次决定；资料范围固定为两个原创方案的六段知识。UI从API加载模板与范围，不硬编码答案。新增引擎可实现相同适配协议；真实资料摄取和通用生成不在当前离线引擎能力内。

## C-005：审批与审计身份不夸大

应用事件记录local-browser及操作说明；原Runtime只支持operator-cli/scripted-test，网页操作者映射为operator-cli。两者用task/run/hash关联，不宣称实名身份。ZIP保持原v1严格合同，原审批和MCP收据可验证，应用操作说明留在本机索引。哈希一致性不等于真实性证明或内容质量通过。

## C-006：行为测试与浏览器复核分开

2026-09-18最终应用测试21/21、0跳过、55.872秒，包含实际P1/P2/P3、真实worker超时、无效操作与安全HTTP；不以源码字符串断言替代功能。浏览器验证了两次显式决定、6条证据、8次MCP、归档/筛选/XSS/窄屏。内置浏览器download事件监听超时；按钮校验成功和HTTP ZIP已证实，操作系统文件落盘待外部浏览器复核。

## C-007：保留原拒绝语义并改善展示

P2将人工拒绝记录为FAILED加HUMAN_REQUEST_REJECTED/REPORT_REJECTED，不能改原图迁就页面。应用派生decision_outcome，让页面和过滤器显示“已拒绝”，原状态/错误继续保留。另修复状态统计布局、步骤条排列、MCP调用数口径、取消确认文案和跳转主要内容行为。

## C-008：浅色研究空间，保持零新增依赖

2026-09-19。按用户确认的浅色极简方向，参考shadcn-admin的导航层级及ui-ux-pro-max-skill公开排版建议，实际使用本地frontend-design；没有安装远程技能或复制第三方源码。继续使用原生HTML/CSS/JS，避免为视觉升级引入构建链。知识页改为目录和阅读双栏，首页模板只预填问题，后端资料范围和双审批不变。重绘后保留资料目录与页签焦点，辅助文字不小于12px。验证分开记录：本轮6项HTTP回归与真实浏览器交互；V1完整21项测试保留原日期与来源。详见docs/UI-REFRESH.md与docs/results/ui-v2.json。

## C-009：毕设适配与开源替换建议（初审，未实施）

2026-09-19。学校公开入口不足以证明满足当届专业验收；不把工程测试等同于毕业设计通过。对比Dify、RAGFlow和已归档Open Deep Research后，建议保留现有工程、借鉴资料管理与研究设计；新的业务定位、技术栈迁移和外部调用均未在本轮实施。完整依据及待确认项见docs/GRADUATION-SUITABILITY-REVIEW.md。

## C-010：G1资料库与既有研究流程隔离

2026-09-21。采用应用私有 Library 表和严格 loopback API，实现授权确认、不可变版本、乐观并发、原文定位和确定性词法检索。新资料暂不进入固定 P2 graph，避免改写 P2 历史失败、gold、预算或真实调用结果；G2 再以冻结版本合同接入 P1/P2/P3。文件正文只由用户选择或粘贴进入，服务器不接受路径，不抓取 URL。15项新增行为测试、36项完整离线回归与浏览器复核通过；合成资料评估不代表真实内容质量。

## C-011：先冻结可验证范围，再接研究执行

2026-09-21。ResearchProjects在应用私有表保存范围manifest与摘要，资料版本按ID固定，不读取latest替代旧版。证据核验由服务端读取原文并比对归属与hash，模型/客户端不能提供可信引文。创建确认仅保存范围，不触发原P2图、审批或MCP；后续执行必须绑定project_id与contract_hash。初稿补齐容量、Unicode、来源唯一与完整性控制，13项新增测试及49项完整回归通过。不同HTTP连接偶发WinError10053保留失败记录，未伪称修复。设计与验收见docs/graduation/G2-PROJECT-CONTRACT.md和G2A-ACCEPTANCE.md。

## C-012：G2-B独立冻结执行适配器

2026-09-22。应用私有task_executions原子保存项目/候选/版本/原文与分段hash的执行快照；固定示例路径保留。P2图/SqliteSaver/零费用OperationLedger/Exporter在隔离子进程复用，P1只复用tokenize_sparse并由应用确定性词元交集排序，P3只使用stdio read_note且逐项核对双回执。候选固定三维，上限4候选、64段、96KiB资料；超出拒绝。P2原报告合同最高版本3，因此初稿外只允许2次人工修订，不修改P2业务代码。修订只改摘要/限制，旧hash失效；新ZIP独立schema/CLI复核原版、分段、报告和审批/审计。不调用真实模型或原账本。源码与证据见G2B-WORKFLOW.md、G2B-ACCEPTANCE.md。

## C-013：包内完整性与身份边界

2026-09-22。新ZIP同时保存冻结资料全文和段落，独立CLI不解压先限制文件数/大小并复算合同、P2渲染、MCP读取和审计。现有哈希均无签名；本机同一OS账户可改变状态，不能称不可抵赖。网页操作映射`operator-cli`，不称真实多用户身份。P2真实内容质量仍未通过；合成脚本矩阵、人工批准和修订不替代内容评分。

## C-014：本机身份模式与既有单用户状态分离

2026-09-22。新 `course-platform-state-v2-auth` 状态目录启用本机 scrypt 账户、随机会话、独立 CSRF、闲置/绝对到期、登录锁定和服务端对象授权；旧 v1 目录保持既有离线演示。两种模式互斥，防止省略启动参数绕过权限。项目创建时冻结所有者与另一名指定审核者；任务权限由 project_id 派生，文档旧版仅向所有者、被指派项目审核者与管理员开放。研究者不能自批，审核者不能编辑资料或报告，管理员审计只保留请求元数据。因原 P2 审批合同仍使用 `operator-cli`，认证用户留在本应用审计，不把 ZIP 哈希称为身份签名。同一 OS 账户可操作 CLI/SQLite，标准库 HTTP 未做公网安全加固；正式远程部署需要另行设计。

资料导入及所有者绑定合并为单个 SQLite 事务，避免并发导入同一来源标签时版本先落盘、权限后拒绝；旧单用户模式不触发绑定。项目创建/绑定仍为两个事务，未绑定项目在身份模式默认拒绝访问，后续可统一事务。

## C-023：评分清单绑定已复核的交付 ZIP

2026-09-22。原 `g4-claims-v1` 清单中的来源段可由填报者任意写入，自身哈希只能阻止之后静默改表。新增 `g4-claims-v2`：从独立复核通过的 ZIP 自动提取完整报告证据矩阵，保存 ZIP 字节摘要与批准报告哈希；每次生成评分/仲裁表和汇总时重新复核 ZIP 并重建清单，逐项相等才允许继续。零证据的 `unknown` 格保留；旧 v1 仅供未绑定来源的格式演示。输出 `source_binding` 只报告机械一致性，不能证明资料授权、报告真伪或内容质量。复核模块去掉对带全局 `sys.addaudithook` 副作用的运行器导入，直接从无该副作用的 `common` 读取文件并显式加载 P2 合同路径；保留原离线 worker 的网络阻断。
