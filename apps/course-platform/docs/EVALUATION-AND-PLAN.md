# 实施与验收计划

1. D0完成需求、架构、API、UI及威胁边界；校对既有Runtime合同。
2. D1实现任务索引、幂等job、固定worker桥和HTTP安全边界，先验证错误与恢复。
3. D2实现可操作UI并通过真实API运行P1/P2/P3闭环。
4. D3完成离线测试、浏览器验证、运行入口、文档、学习总结和结果记录。

固定验收分组：输入/状态校验；HTTP Host/Origin/CSRF/静态路径；幂等与队列互斥；任务持久化与重启中断；真实engine两门/拒绝/恢复/ZIP验证；UI操作与窄屏；旧整合回归。普通单元测试不访问网络；HTTP测试只连接自己启动的回环服务器；engine测试只用新临时目录和脚本模型。

功能必须从实际调用和输出断言，不使用检查源码字符串的伪功能测试。不将界面正常显示、引用数或助手评分作为内容质量通过。记录首次失败、修复和最终结果；不改P2旧gold、真实质量失败或账本。

最终材料包含README、.env.example（只说明不需要密钥）、一键启动、依赖复用说明、固定测试、截图/演示、已知限制、RETROSPECTIVE、LLH_Study和开发交接。完成定义是当前声明的本机离线课设工程版；学校最终验收、独立讲解、新机器安装和远程部署仍需独立验证。
