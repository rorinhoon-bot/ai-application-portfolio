# 研据工作台：课设需求分析 v1

## 问题与目标

把零散的知识处理、研究工作流和MCP工具组合成一个可观察、可审批、可追溯的研究交付系统。面向需要展示完整软件工程过程的学生，以及检查过程与证据的教师。系统展示的核心价值是控制研究过程与交付边界，不将离线脚本结果宣传为真实模型质量。

产品名称：研据工作台。课设题目建议：基于可追溯证据与人工审批的AI研究交付系统设计与实现。学校后续若要求数据库建模、前后端接口、权限、部署、特定框架或论文模板，可在本工程基线上调整；不得预设已经满足未给出的评分标准。

## 用户与使用场景

本机操作者创建研究任务，检查问题和资料范围后批准研究；系统实际执行P1解析、P2图与P3 MCP调用；操作者审阅报告和引用，再批准导出，或拒绝/取消。教师可以查看任务过程、来源与hash、审计、已有评估证据及已知限制。当前两者都是同一可信本机用户的使用视角，无账号认证或角色隔离声明。

## 功能需求

| 编号 | 功能 | 验收标准 |
|---|---|---|
| F01 | 工作台 | 展示真实任务计数、待审批任务与最近任务；空状态引导创建 |
| F02 | 创建与管理 | 标题、问题校验；查询/状态过滤；复制任务；归档/取消归档不删除审计 |
| F03 | 异步任务 | 创建/决策返回job；执行时显示真实忙碌状态；刷新或重启保留索引 |
| F04 | 需求审批 | 显示问题、固定来源和成本范围；明确确认与说明；绑定request_hash |
| F05 | 报告审批 | 显示完整草稿、证据及审校发现；绑定report_hash；未批准不能下载正式交付 |
| F06 | 知识与证据 | 浏览六段实际P1解析知识，按文本检索；引用定位到来源、章节和hash |
| F07 | 报告交付 | 已完成任务查看报告并下载ZIP；下载前复核审批/审计/文件关联 |
| F08 | 运行审计 | 查看应用事件、两门决定、MCP调用及hash；不输出密钥/主机路径 |
| F09 | 恢复与幂等 | 重复request_id不重复创建；hash过期拒绝；重启中断任务需显式恢复 |
| F10 | 评估与边界 | 显示有来源的历史工程结果；真实内容质量标记未通过 |

## 非功能需求

默认只绑定127.0.0.1；新状态独立目录；未知参数拒绝；正文不作为HTML/命令执行；路径白名单；Host/Origin和CSRF防护；安全响应头；API不回显内部异常。请求体、队列、任务数、worker时间与输出有上限。桌面和窄屏可用，键盘焦点可见，错误与空状态提供下一步。

## 明确范围

当前实现为本机单用户离线完整交付闭环；固定graph-plan/chain-plan、tool-calling/human-approval/recovery范围。自定义问题不能扩展资料边界；界面必须展示这一点。真实模型调用、任意知识上传、P1实时API/向量检索、远程多用户、云部署、生产认证与独立内容质量评审暂未启用。预算不得因UI新增或新数据库而重新获得额度。

## 毕设增量入口

G1与G2新需求见graduation/PRD.md及graduation/G2-PROJECT-CONTRACT.md。G2-A只完成研究范围和证据核验，任务/报告关联待G2-B，旧需求的固定演示范围继续有效。
