# G4 正式要求与独立内容评价准备

2026-09-22，仅完成离线方案；**未取得教师当届要求、未下载正式资料、未开展真实内容质量验收**。本方案由助手拟定，需与教师要求和资料授权核对后冻结。

## 先收集的输入

1. 当届软件工程毕业设计/课设的题目、功能、工作量、论文、演示、查重和评分条款原文及版本日期。建立“条款编号—系统功能—测试/截图/论文证据—差距—教师确认”矩阵；不得凭其他届或公开入口推断符合。
2. 明确研究场景与资料使用权。每篇正式资料登记作者/发布者、地址或文件名、取得日期、许可/引用条件、允许进入本机演示与论文的范围、更新频率。未经授权的资料不导入。
3. 确定独立标注者和盲评方式。标注不能由生成同一报告的脚本或模型自评替代；记录分歧及仲裁，不把人工审批动作当作内容评分。

## 预注册评估集

先拟问题与判定规则，再冻结语料版本、项目合同、问题集及阈值。至少覆盖可直接回答、同义/近义表达、跨文档比较、冲突证据、过期资料、资料外问题、证据缺失、审批后修订与恢复。每题单独记录可接受来源段、必须说明的限制、应拒答/需人工判断情形。训练/调试题与保留测试题按资料源分离；报告中同时披露样本量、各类数量和置信区间，不只报总正确率。具体题数和阈值待资料规模与教师要求确定，不事后按结果调整。

## 分项判定

| 维度 | 可复现证据 | 不能替代它的证据 |
|---|---|---|
| 检索 | Recall@k、MRR、段落定位、无依据返回空、延迟，逐题来源版本 | G1 合成 18/18 Hit@1 |
| 工具安全 | 越权、路径、无网、超时、审计与回执的行为测试 | 只检查源码字符串 |
| 工作流 | 双审批、过期 hash、checkpoint 恢复、幂等、ZIP 复核 | 页面显示“完成” |
| 报告内容 | 盲评事实支持率、关键遗漏、冲突处理、限制充分性、错引与拒答 | 引用存在、格式正确、模型自评、审核按钮 |
| 课设符合性 | 教师条款逐项映射和缺口关闭记录 | 本机自动测试全通过 |

报告评分单元按“一个可核验主张及其引用”拆分；标注为支持、部分支持、不支持、无法判断，并记录来源段 ID、错误类型和严重度。两名独立标注者先各自评分，披露一致率和分歧；若只能有一名，标注为单评审限制。工作流、安全和内容分别给结论，不能合成一个“全部完成”分数。
