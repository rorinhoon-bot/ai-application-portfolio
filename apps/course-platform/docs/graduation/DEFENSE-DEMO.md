# 五分钟答辩演示草案

供学习者**亲自练习**，不是已完成的学生独立演示。题目方向为“面向软件项目技术选型的可追溯研究与审批系统”；导师当届题目及评分细则尚未取得，正式稿须对照后修改。

演示前准备全新身份状态目录和三个本机演示账户；口令仅在交互提示输入。准备两篇标明“助手原创合成”的 Markdown 资料及一个比较问题。先离线运行环境探针与测试，确认真实模型调用为0。

| 时间 | 操作 | 必须说清 |
|---|---|---|
| 0:00–0:40 | 工作台与问题 | 用户是技术选型研究者和审核者；系统关联资料、决定、工具调用与报告。当前仅本机离线工程基线。 |
| 0:40–1:30 | 研究者导入资料、创建项目、冻结版本并指定审核者 | 原文、来源、版本 ID 与 hash 固定；模型不能扩大范围。 |
| 1:30–2:15 | 审核者检查并批准范围 | 批准前模型和 MCP 调用为0；研究者不能自批；决定绑定请求 hash。 |
| 2:15–3:15 | 展示报告、证据定位、MCP 审计和 checkpoint | P1提供分词，应用按词元交集排序；P2管图、恢复与双审批；P3只读取证。引用格式不能证明内容正确。 |
| 3:15–4:10 | 研究者修订摘要/限制，审核者重新批准 | 修改使旧报告 hash 的批准失效；应用会话用户和 P2 内部 `operator-cli` 是不同记录边界。 |
| 4:10–4:40 | 下载 ZIP，用 `frozen_bundle_cli.py` 复核 | 可验证资料快照、报告、审批和 MCP 回执一致；hash 不是身份签名或事实证明。 |
| 4:40–5:00 | 评估与限制 | 55项离线回归通过；P2真实内容历史验收未通过，预算已封顶；正式资料和学校要求待核对。 |

现场时间不足时，保留冻结来源、两级审批、证据/工具审计、限制四个画面。实际结果数量以当次页面为准，不背旧截图数字。若学校现场不便切换账户，可用已脱敏本机录屏，但须注明录制与助手参与情况。

追问准备：为何不能自批（服务端对象授权）；为何冻结版本（审批后的来源不漂移）；P1/P2/P3分别做什么（分词、状态图、MCP读取）；为何不能公开部署（本机HTTP和同OS账户可改SQLite）；学生本人做了什么（按真实参与说明，当前独立实现与讲解未验收）。真实模型、教师合规和内容质量不能用工程测试代替。见 [G3验收](G3-ACCEPTANCE.md)、[G4计划](G4-REAL-DATA-AND-COURSE-PLAN.md)及[隔离复现](../REPRODUCIBILITY.md)。
