# G3 身份与权限需求

2026-09-22。目标：在独立、全新本机状态目录演示研究者提交、另一名审核者批准的可追溯流程。旧单用户状态目录保持 G2-B 模式，不做隐式迁移。实现者为助手协作，非学生独立完成证据。

## 用户故事与验收

- 管理员通过本机交互式命令创建账户；无内置密码、无网页注册、无密码写入仓库。研究者登录后导入自己的资料、冻结项目、选择审核者并创建任务。
- 指派审核者可查看指定项目和任务，批准或拒绝范围及报告；不能编辑资料、创建研究任务、修订报告。研究者可修订自己报告、归档和恢复任务；不能批准自己的范围或报告。管理员可读全部记录，管理账户；只在不是项目所有者时执行审核决定。
- 未登录读业务 API 返回 `UNAUTHENTICATED`。跨项目标识读写返回 `NOT_FOUND`，角色不符返回 `ACCESS_DENIED`。失败操作写入独立审计，不记录口令、Cookie、CSRF 或正文。
- 会话采用随机令牌、服务端摘要、HttpOnly/SameSite Cookie、空闲及绝对过期、登出撤销。每会话单独 CSRF。登录错误有固定窗口上限。
- 新身份状态与旧状态标记互斥。没有管理员时服务拒绝启动。服务仍仅监听 127.0.0.1；不宣称公网、多租户或操作系统账户间隔离。

## 非目标与边界

固定示例任务在身份模式停用，仅允许从冻结项目创建任务。P2 内部 `operator-cli` 保持原合同，应用认证事件另行关联；不能说 P2 已认识真实用户。G3 只验权限与工作流，真实资料内容质量、学校当届要求、远程部署属于 G4/后续。
