# G3 权限架构与威胁边界

2026-09-22。`--auth-required` 只接受新建 `course-platform-state-v2-auth` 状态目录；缺此参数打开该目录必须失败。原 `v1` 目录不能用身份模式打开。管理员先由本机 CLI 在空目录创建，HTTP 启动要求管理员存在。

`AuthManager` 在应用私有 SQLite 保存用户（scrypt 盐和摘要）、会话（只存令牌 SHA-256，独立 CSRF、到期时间）、登录失败窗口、文档所有者、项目所有者与审核者、权限审计。身份绑定由服务端会话决定；请求体中的身份字段一律不受信。项目创建时前置校验所有冻结版本归属研究者，审核者必须是启用的另一个账户；项目返回前写入不可重派的绑定。动态任务访问从其冻结 `project_id` 派生，不接受未绑定固定任务。

资料导入在 `Library.import_text` 的单个 SQLite 事务内绑定 `document_owners` 与新版本/请求记录；并发来源标签碰撞先核对所有者，失败整体回滚。项目归属仍在项目创建后的独立事务写入，失败时未绑定项目对 HTTP 身份模式默认不可见。

读权限：研究者看自己文档、项目、任务；审核者看被指派项目、任务及其冻结资料版本；管理员可读全部。库检索仅限研究者本人资料，审核者看冻结项目而非全库。写权限：研究者导入/修订自己的资料、建项目/任务、修订/归档/恢复自己任务；指派审核者审批/拒绝；管理员仅负责账户、本机审计及非本人项目审核。审批始终检查项目所有者与会话用户不同。所有读取、搜索、下载和幂等重复请求都先做权限判断；未绑定对象默认拒绝。

服务器继续执行 Host/Origin/CSRF、请求大小和 JSON 合同。登录由同源 Origin 与服务启动时随机生成的 CSRF 保护；业务变更用每会话 CSRF。令牌只在 Cookie 中传递，不进 URL/JSON/日志。HttpOnly/SameSite=Strict Cookie 在本机明文 HTTP 下不等于网络传输保密；远程部署必须重新设计 TLS、反向代理及账户运维。SQLite/ZIP 对同一操作系统账户不防篡改，不是法律意义的不可抵赖签名。

P2 图的审批角色仍为 `operator-cli`：应用在自身审计保留认证用户、项目、任务、请求 ID 和决定摘要；P2 checkpoint/报告哈希与该请求关联。导出包若不包含可独立校验的认证日志，则不得声称离线 ZIP 独立证明操作者身份。
