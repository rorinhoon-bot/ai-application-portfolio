# UI设计与复核

> 以下保留V1设计记录。当前浅色极简版本、GitHub参考及本轮验证见 [UI-REFRESH.md](UI-REFRESH.md)；新版截图见screenshots/ui-v2/。

主题是研究档案与审批工作台。采用深蓝侧栏、白色工作纸、靛蓝进度轨与琥珀审批提示；最有辨识度的部件是贯穿任务详情的“需求确认—研究—报告确认—交付”流程轨，颜色只编码状态。

Token：画布`#edf2f7`、纸面`#ffffff`、侧栏`#152b46`、正文`#20334a`、主操作`#375cce`、待审批`#a86411`。字体优先Segoe UI/Microsoft YaHei，中文正文14px/1.65，页面标题28px/1.3，辅助12px；代码hash用等宽字体且允许换行。不用外部字体或装饰性渐变。

布局左对齐：固定窄侧栏承载工作台/研究任务/知识资料/评估与说明；主区域首屏是当前工作而非宣传数字；任务列表使用紧凑表格；详情左主内容、右审批区；窄屏导航转横向，审批区落到正文下方。

```text
导航 | 标题与“新建研究”
     | 当前待处理 / 流程说明
     | 最近任务表：问题、状态、来源、更新时间
     | 任务详情：流程轨
     | [报告 / 证据 / 审计]     [当前决定]
```

对照需求复核：曾考虑普通指标卡仪表盘，但本产品主要操作是读证据并审批，因此将待审批任务和可审阅正文置于首屏，指标缩为小型文字统计；知识页显示真实段落和来源，避免空壳文档卡。没有数据时明确“尚无研究任务”，不填入伪造的运行历史。运行中禁用重复提交，失败给恢复或复制新任务入口。审批必须弹出独立确认框，显示对象摘要和hash，不隐藏真实限制。

验收包括桌面与窄屏截图、真实建任务/两次审批/下载、拒绝路径、刷新后持久状态、键盘焦点、长文本与HTML样本显示安全。自动测试验证行为，截图只记录真实运行结果。
