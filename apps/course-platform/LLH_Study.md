# 研据工作台学习与开发复盘

本轮由助手协作设计与实现。以下用于后续学习、代码走读与自测，不代表学习者已经独立掌握。

## 原理与技术栈

浏览器展示任务、接收操作者决定；HTTP验证输入并快速返回；后台进程执行既有工作流；SQLite索引保留页面可恢复状态。P1解析资料并绑定来源，P2决定下一节点并维护checkpoint，P3通过MCP执行受限工具。审批绑定内容hash，最终导出再次核验。

前端为HTML/CSS/JavaScript，后端HTTP/SQLite/线程池/子进程均Python标准库。已有P2 LangGraph与P3 MCP由各项目隔离环境加载。没有新增框架或真实API调用。

## 核心代码路线

1. `domain.fields/text/identifier/decode`：拒绝未知字段、非法ID、重复JSON键；用户输入不能变成路径。
2. `Store.reserve`：在同一事务内写task/job；request_id重复检查payload hash，避免重复创建。不同内容不能复用同一标识。
3. `Service._run`：业务在后台；结果回写索引；稳定错误不会泄露异常与本机路径。
4. `OfflineEngine.call`：固定解释器、脚本、环境与超时；不执行客户端提供的命令。
5. `engine_worker.handle`：复用Runtime与审批hash；不将工作流直接导入HTTP进程，因为它禁止网络socket。
6. `engine_worker.export`：从完成run读取固定文件，验证bundle后压缩；不把任意本地目录打包。
7. `web/app.js`：UI消费严格API，动态文本统一转义；确认对话框记录hash快照，而非自动批准最新版本。

## 关键取舍

- 原生前端降低新依赖和安装成本，适合当前规模；更复杂页面可在老师指定后迁移框架。
- 新建任务索引不替代checkpoint。前者支持列表与操作记录，后者恢复业务图。
- 单后台队列简化并发安全，代价是吞吐有限；当前不能宣传高并发。
- 固定资料与脚本模型让离线故障可重现，代价是不具备通用知识问答能力。
- 应用日志与MCP审计分层。hash能发现不一致，却不是数字签名或内容真实保证。

## 测试与复盘

21项行为测试覆盖HTTP安全、幂等、过期审批、容量、重启、实际worker超时和真实P1/P2/P3全流程。浏览器检查揭示了布局、工具计数口径和取消文案问题；这些问题无法由后端测试发现。UI渲染正确也不能证明内容质量，因此两者分别记录。

工程测试通过仅说明被测条件内行为符合合同。P2真实内容仍未通过；6/6引用单元格由固定脚本产生，不能拿作真实模型正确率。

## 面试问题与自测

- 为什么需要两个审批门？分别约束研究范围和最终报告版本；它们不能互相替代。
- 浏览器重试为什么不生成两份报告？解释request_id、payload hash、busy、原Runtime制品幂等各自的边界。
- 为什么关闭页面任务还继续？HTTP与后台worker解耦；页面重新读取持久化索引。
- 为什么不能把本机服务直接暴露公网？无认证/租户隔离，HTTP实现和资源控制仅面向本机演示。
- 报告有引用就可信吗？不能，仍需事实支持、来源质量和独立内容评价。
- 如何证明P3实际参与？指出真实stdio调用、8条工具事件、begin/end回执与交付复核。

独立练习：画出一次审批从UI到checkpoint的数据流；定位过期hash拒绝测试；解释一次超时后的恢复；演示取消后0模型调用；在不修改原模块和测试gold的前提下新增一个纯展示字段及行为验证。


## G1资料库复盘

`library.py`把资料写入本应用自己的 SQLite 表。`document_id`由来源标签摘要决定；`version_id`由元数据和正文摘要决定；正文更新不会覆盖旧行。`expected_version`是乐观并发条件，`request_id + payload_hash`是导入幂等边界。事务同时写版本、请求和审计，审计只留 hash/字节数/段数，不留正文。

检索先把英文词和中文相邻双字变成词元，再用长度归一、逆文档频率和精确短语加分排序；它是确定性词法检索，不是语义向量检索。空结果必须保持空，不由系统补答案。页面所有资料字段先转义，HTML样例只能显示为文字。

G1自测：解释为什么来源标签不是网页抓取地址；说明重复请求与并发修订分别如何处理；指出旧版为什么只能查看而不能原样恢复；设计一组困难负例，证明合成 Hit@1 不等于真实内容质量；画出资料版本、冻结研究任务、报告审批哈希之间的未来 G2 关联。

## G2-A冻结范围复盘

来源库的最新版本会变化，研究项目要保留当时选择的version_id。contract_hash绑定问题、约束与manifest；chunk_id和内容hash用于逐段核验。request_id幂等解决重复提交，BEGIN IMMEDIATE解决创建与容量检查竞争；二者不代替人工审批。

本阶段由助手实现。独立自测：更新资料后为什么旧研究仍用旧版？为什么核验通过不等于内容正确？指出拒绝越界证据的测试；解释后续报告改动如何使批准失效；说明本机hash为什么不能证明操作者身份。

## G2-B冻结执行复盘

应用在任务创建时把所选候选、版本全文和分段固定成execution_hash；P2工作流另有范围审批与报告审批。范围审批前脚本模型与MCP读取均为0。批准后，P1解释器的`tokenize_sparse`产词元，应用只按词元交集排序；P3的`read_note`读取命中段落，P2的真实V2图在独立checkpoint推进。这个P1调用不等于P1向量服务或BM25评估。`FrozenStore`要同时比对P3正文、sha、快照和begin/end回执，否则“模型引用了某段”只是文本声明。

人工修订只改`executive_summary`和`limitations`，保存旧版及新hash，令原批准无效。P2合同报告版本上限3，所以本阶段最多两次修订。`frozen_bundle_cli.py`核验ZIP文件清单、原始版本全文与分段、报告渲染、审批hash、引用和MCP回执；同一OS账户仍能篡改无签名状态，因此不能把哈希当身份认证。P2脚本模型可能给出推荐，但合成资料没有独立内容评分。

本阶段由助手实现，学习者独立实现和讲解待验证。自测：为什么不能在HTTP进程导入P2 Runtime？说明tokenize_sparse、排序和P3读取分别在哪里执行；画出project_id、execution_hash、P2 run_id与checkpoint的关联；解释改动报告摘要后为何必须重审；设计“报告引用了别的候选段落”的拒绝测试；说出零费用ledger与P2真实¥5账本的隔离边界。

## G3身份与权限复盘

身份模式使用全新状态目录；启动标记阻止旧无认证模式打开同一数据。`auth_cli.py`从终端交互读取口令，`auth.py`用 scrypt 加盐保存摘要，Cookie 原值只发给浏览器，服务端只保存令牌 SHA-256。会话有空闲和绝对寿命、登出撤销；登录失败窗口限制猜测。前端隐藏越权按钮只改善操作，真正的读、检索、下载、审批权限必须由 `server.py` 每次根据会话用户和冻结项目审核者校验。CSRF 防止浏览器携带 Cookie 被其他站点驱动；它不替代对象授权。

研究者所有权、文档版本和项目审核者分开存储。审核者可以读其项目冻结的旧版资料，却不能搜其他人的库；研究者只能修订自己的报告，不能自己批准。审批依然进入原 P2 的 `operator-cli` 合同，应用权限审计单独保留本机会话用户和请求关联。失败请求也记录允许/拒绝结果，但不记口令、Cookie、CSRF 或资料正文。

本阶段由助手实现；学习者独立讲解尚未验证。自测：为何仅隐藏“批准”按钮不能阻止自批？说明重复请求为什么仍须先查对象权限；画出用户、项目、审核者、任务、P2 checkpoint 和报告 hash 的关系；解释退出登录和会话过期的差别；找出一个“新状态被旧模式打开”的失败测试；说出同一 OS 账户能修改 SQLite 时，为什么这仍是本机演示权限而非公网多租户安全。
