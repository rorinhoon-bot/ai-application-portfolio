# 作品验收标准

## 1. 问题与用户

- README 能用一句话说明解决什么问题。
- 明确目标用户、输入、输出和不处理范围。
- `docs/PRD.md` 有可检查的验收标准。

## 2. 可运行

- 新环境可按文档安装依赖并启动。
- `.env.example` 列出所需变量。
- 不要求读者猜测命令、目录或配置。

## 3. 代码质量

- 核心逻辑按职责拆分。
- 配置、业务逻辑和外部调用分离。
- 错误信息可理解。
- 依赖版本可复现。

## 4. 测试

- 至少覆盖主要成功路径。
- 覆盖缺少配置、非法输入和外部服务失败。
- 高风险或写操作覆盖权限与确认边界。

## 5. AI 评估

- 使用固定测试集。
- 保存模型、Prompt、参数和数据版本。
- 有基线结果。
- 有失败样例和错误分类。
- 优化后使用同一测试集回归。

## 6. 安全

- 无真实密钥进入 Git。
- 不信任模型生成的 SQL、路径、命令和工具参数。
- 文件访问有白名单与路径规范化。
- 数据来源、隐私和许可证有说明。

## 7. 展示

- README 有功能说明、架构、安装、运行、测试、评估和限制。
- 至少一张截图或一个短演示。
- 能在五分钟内介绍问题、方案、难点、结果和改进。

## 8. 完成检查

只有全部满足，才能把 `STATUS.md` 改为 `completed`。
