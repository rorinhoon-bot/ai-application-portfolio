# 能力缺口与偏好

## 已确认目标

- 作品集主要用于 AI 应用开发岗位求职与实习。
- 当前路线学习以概念为主，代码练习很少。
- 交接包不把节点完成状态写成独立实现能力。
- 愿意后续安装 Docker，希望主要空间使用 H 盘。

## 未确定信息

- 每周可投入时间：未确定，不写入排期承诺。
- API 预算：未确定，项目设计需支持低成本或本地替代方案。
- 目标公司、行业和岗位描述：尚未提供。
- 是否需要公开部署：尚未确定。
- 是否使用真实业务数据：尚未确定。

这些信息不阻塞第一阶段。选择部署平台、模型和项目截止时间前再确认。

## 主要能力缺口

### 1. Python 工程基础

- Python 当前无法从命令行直接调用。
- 尚无已验证的虚拟环境、依赖锁定、项目结构和测试流程。
- 首个正式作品前需要小型工程热身。

### 2. 从概念到代码

- 已学习 RAG、Agent、LoRA、MCP 等概念。
- 缺少从零实现、运行、调试和解释代码的证据。
- 作品开发应采用“小步实现—运行—测试—记录”的节奏。

### 3. 评估能力

- 已学习评估术语。
- 缺少真实数据集、基线、指标、失败样例和优化前后对比。
- 每个作品必须至少有一个固定评估集。

### 4. 工程质量

- 缺少 Git 提交历史、自动测试、异常处理、日志和配置管理。
- 缺少 README、架构图、部署说明和演示材料。

### 5. 求职表达

- 尚未形成“问题—方案—实现—评估—结果—限制”的项目故事。
- 需要把技术名词转成可验证的业务价值。

## 学习偏好

- 说明简单、直白、范围清楚。
- 核心概念配短例子。
- 不希望一次输入大量复杂提示词。
- 希望 Codex 主动整理上下文并推进，但遇到不确定事项先询问。
- 实现阶段应获得指导，而非只得到完整代写结果。
- P0、P1、P2、P3 每个项目完成后创建项目级 `LLH_Study.md`，用于复习项目原理、技术栈、代码流程、评估结果和面试问答。

## 教学约束

- 不假定节点打卡等于掌握。
- 不因对话中出现代码示例便声称学习者运行过代码。
- 每次新技术先给最小解释，再进入实际操作。
- 关键代码由学习者参与编写和解释。
- 同一错误连续出现时，更新项目指导文件或检查清单。
