# AI 应用开发作品集交接说明

## 作品集目标

面向 AI 应用开发岗位求职与实习，建立能运行、能测试、能评估、能解释的作品，而非继续收集知识总结。

## 学习者起点

- 已完成 PRE、L1～L5 共 28 个概念节点。
- 熟悉主要术语和系统组成。
- 代码与工程实践很少。
- 所有关键技能当前统一为等级 1：已学习概念，独立实现尚未验证。

## 总体策略

先完成一个不作为主作品的工程热身，再完成三个求职作品。

```text
P0 工程热身
   ↓
P1 带引用的知识库问答
   ↓
P2 LangGraph 研究报告工作流
   ↓
P3 本地 MCP 工具服务
   ↓
作品集网站与求职材料
```

## P0：工程热身，不作为主作品

目标：验证 Python、Git、API、JSON Schema、环境变量和测试。

建议功能：结构化内容生成器。

最低要求：

- 创建 Python 虚拟环境。
- 从环境变量读取 API Key。
- 输入自然语言需求。
- 输出符合 JSON Schema 的结构化结果。
- 处理缺少密钥、超时、非法 JSON 等错误。
- 至少 5 个自动测试。
- 至少两次有意义的 Git 提交。

完成 P0 后再进入 RAG，避免同时学习工程基础和复杂 AI 架构。

## P1：带引用的知识库问答

主要验证：PRE、L1、L2、L5-1。

必须包含：

- 文档导入、清洗与切分。
- Embedding、向量检索和真实元数据。
- 答案引用文件名、页码或段落。
- 无资料时拒绝编造。
- 至少 20 条固定评估问题。
- 检索相关性、召回、忠实度或等价指标。
- 一次优化前后对比。
- README、架构图、截图和已知限制。

可选优化：关键词 + 向量混合检索、Reranker、上下文压缩。

## P2：LangGraph 研究报告工作流

主要验证：L3，并复用 P1 的检索能力。

建议节点：

```text
需求确认
→ 规划
→ 检索
→ 写作
→ 审校
→ 人工确认
→ 输出报告
```

必须包含：

- 显式状态模型。
- 条件分支和最大重试次数。
- 工具调用和参数校验。
- Human-in-the-loop。
- 中断恢复或持久化状态。
- 外部副作用幂等性。
- 成功、失败、人工介入三类测试。
- 任务耗时、调用次数或成本记录。

多智能体只作可选扩展。先证明单工作流确有必要，再引入 AutoGen 或 CrewAI。

## P3：本地 MCP 工具服务

主要验证：PRE、L3-2、L5-3。

建议能力：

- `search_notes(keyword)`：只读搜索笔记。
- `create_task(title, description)`：创建任务。
- 一个只读 Resource。
- JSON Schema 参数约束。
- 白名单目录和路径穿越防护。
- 写操作确认边界。
- 清晰错误对象和自动测试。
- 一个实际 MCP Host/Client 接入演示。

## 后置项目

以下技术不进入首批三个作品：

- LoRA 微调与量化部署。
- A2A 跨 Agent 通信。
- GraphRAG。
- 多模态业务原型。

原因：当前需要先证明基础工程、RAG、Agent 和 MCP。首批作品完成后，再根据目标岗位描述选择一个专项补强。

## 每个作品的统一目录

```text
project/
├─ README.md
├─ STATUS.md
├─ DECISIONS.md
├─ .env.example
├─ docs/
│  ├─ PRD.md
│  └─ ARCHITECTURE.md
├─ src/
├─ tests/
├─ evals/
├─ demo/
└─ RETROSPECTIVE.md
```

## 统一完成标准

- 新用户能按 README 启动。
- 密钥未写入源码或 Git。
- 有自动测试和固定评估集。
- 有失败案例和错误处理。
- 有量化结果，不只展示成功截图。
- 有架构图和关键技术取舍。
- 有演示截图或视频。
- 有已知限制和后续改进。
- 学习者能在五分钟内解释项目。

## Codex 指导原则

- 每次任务先读本交接包和当前作品 `STATUS.md`。
- 不重复整套概念课；实现到对应环节时复习。
- 先让学习者做需求、设计或核心实现，再审查。
- 不一次生成整个作品。
- 每个阶段结束时更新 `STATUS.md` 和 `DECISIONS.md`。
- 信息不足、需要安装软件、产生费用或改变系统设置时先询问。
