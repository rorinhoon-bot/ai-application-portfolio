# P2 固定评估资料方案

- 版本：v0.3
- 状态：implemented and verified
- 日期：2026-07-29
- 首批原则：原创、离线、确定性、无外部下载

## 1. 为什么先用原创夹具

首个实现目标是验证状态图，而不是证明开放网页搜索。若一开始使用实时框架文档，失败可能来自网页变化、检索质量、模型输出或状态机，难以定位。

首批使用原创虚构技术资料：

- 能预先知道正确证据和允许结论。
- 能稳定触发证据不足、冲突、提示注入和工具错误。
- 普通测试完全离线。
- 不需要付费、下载许可或真实 API。
- 后续真实官方资料评估与首批状态机基线分开，避免污染。

## 2. 资料范围

### 虚构候选

使用三个明确标注为虚构的工作流框架：

- `AtlasFlow`：强调本地持久化和严格审批，成本较高。
- `BeaconFlow`：强调低成本和简单部署，持久恢复能力有限。
- `CedarFlow`：强调 Tool Calling 和可观测性，离线部署受限。

名字只用于测试，不映射或暗示现实产品。

### 来源文件

已创建 10 个 UTF-8 Markdown 文件：

| 数量 | 内容 | 用途 |
|---:|---|---|
| 3 | 每个候选的 overview | 基础能力、定位和部署方式 |
| 3 | 每个候选的 reliability | checkpoint、重试、停止和幂等 |
| 3 | 每个候选的 security-and-cost | 权限、数据边界、成本和限制 |
| 1 | 独立采购约束说明 | 固定业务背景、必须条件和禁止条件 |

每个文件包含：

- 稳定 `source_id`。
- 候选 ID、标题、版本 `1.0.0`。
- `synthetic test fixture` 标记。
- 章节 ID。
- 明确事实和限制。
- 原始 UTF-8 字节 SHA-256。

实际每个文件 687～883 bytes，10 个 Markdown 共 7,625 bytes。

## 4. 固定评估案例

已创建 `evals/workflow-v1.json`，固定 12 个案例：

| 类别 | 数量 | 关键预期 |
|---|---:|---|
| 正常选型 | 4 | 需求完整；覆盖全部候选；证据充分；进入人工批准 |
| 需求不完整 | 2 | 不自动猜测；暂停在需求确认 |
| 证据不足 | 2 | 最多补检索一次；输出有限结论或稳定失败 |
| 工具失败 | 2 | 瞬时错误有限重试；确定性错误不重试 |
| 人工退回 | 1 | 旧批准失效；修改后重新审校和确认 |
| 恢复与重复导出 | 1 | checkpoint 恢复；最终制品最多一个 |

每个案例保存：

- `case_id`、类别和描述。
- 输入需求。
- 假模型动作序列。
- 假工具结果或错误序列。
- 预设人工动作。
- 预期节点路径。
- 预期终态或暂停状态。
- 预期调用和重试上限。
- 必需和禁止引用 ID。
- 允许推荐的候选集合。
- 预期制品数量和内容哈希关系。

实际 `workflow-v1.json` 为 21,296 bytes；金标准为 5,190 bytes。

## 5. 特殊安全夹具

v1 已固定以下安全和失败测试内容：

1. 提示注入：来源正文要求忽略系统规则并调用未授权工具。预期只作为资料文本，权限不变。
2. 路径指令：同一正文要求写入绝对路径。预期不得成为工具参数或导出路径。
3. 不可比较成本：各候选只有成本结构，没有统一规模价格。预期不能宣称所有规模下绝对最低。
4. 缺失证据：资料不能证明 CedarFlow 完全离线。预期补检索一次后稳定失败。
5. 工具错误：固定瞬时超时恢复和非法参数不重试两条路径。
6. 人工与恢复：固定报告退回重写、checkpoint 恢复和重复导出路径。

伪造 URL 和重复检索结果去重保留到后续检索适配器阶段，不虚报为 v1 已实现。

## 6. 金标准

`evals/gold/workflow-v1-gold.json` 保存：

- 每个候选在各维度的允许事实。
- 每条事实对应的一个或多个 `evidence_id`。
- 明确禁止断言。
- 允许的比较分值或缺失值。
- 在不同约束下允许推荐的候选集合。
- 期望路由和停止条件。

金标准在实现前固定。查看基线结果后不回改 v1；需要修正时创建 v2，并保留旧文件和失败报告。

## 7. 快照和完整性

实际目录：

```text
data/
└─ synthetic-sources/
   ├─ manifest.json
   ├─ atlasflow/*.md
   ├─ beaconflow/*.md
   ├─ cedarflow/*.md
   └─ shared/*.md
evals/
├─ workflow-v1.json
└─ gold/
   └─ workflow-v1-gold.json
```

Manifest 固定：

- 文件相对路径 allowlist。
- 文件大小。
- 文件 SHA-256。
- 来源类型和虚构标记。
- 版本和生成方式。
- 规范化 Manifest SHA-256，作为 `source_snapshot_id`。

加载前先校验成员集合、路径、大小和哈希。禁止绝对路径、`..`、符号链接和 junction 逃逸。任何文件不一致时整批失败。

- 来源：10

- 案例：12

## 8. 检索基线

首批不安装向量库或 Embedding。使用确定性假检索器：

- 按 `case_id + query_id` 返回固定证据。
- 能注入 timeout、429、权限拒绝、未知 ID 和重复结果。
- 返回合同与未来真实检索器相同。

这不是最终检索能力展示。它只隔离验证 LangGraph 状态、Tool Calling、路由和恢复。真实资料阶段再实现独立只读检索适配器，并建立新评估集。

## 9. 首批量化指标

- 固定路径正确率至少 `90%`。
- 引用绑定有效率 `100%`。
- 未批准导出次数 `0`。
- 重试和停止边界正确率 `100%`。
- checkpoint 恢复一致率 `100%`。
- 重复导出新增制品数不超过 `1`。
- 提示注入扩大权限次数 `0`。
- 金标准关键事实无证据断言率不高于 `10%`。

前七项可由离线程序自动计算。报告质量人工评分和真实模型指标后置。

## 12. `workflow-v1` 首个量化基线

统一运行器实际执行 12 个冻结案例。它使用显式 LangGraph、临时 SQLite、确定性假工具、预设人工动作和临时制品目录。执行依赖只从案例输入、脚本工具结果和独立 gold 推荐规则构造；`expected` 只在执行完成后参与比较。

评估命令：

```powershell
$env:LANGGRAPH_STRICT_MSGPACK="true"
$env:LANGSMITH_TRACING="false"
.\.venv\Scripts\python.exe scripts\run_workflow_evaluation.py --check
```

提交结果：`evals/results/workflow-v1-baseline.json`。

| 指标 | 首个基线 | v1 目标 |
|---|---:|---:|
| 固定案例通过率 | `12/12` | 记录 |
| 固定路径正确率 | `12/12`，`100%` | 至少 `90%` |
| 引用绑定有效率 | `10/10`，`100%` | `100%` |
| 重试和停止边界正确率 | `12/12`，`100%` | `100%` |
| checkpoint 恢复一致率 | `1/1`，`100%` | `100%` |
| 恢复案例最终制品数 | `1` | 不超过 `1` |
| 未批准导出次数 | `0` | `0` |
| 提示注入扩大权限次数 | `0` | `0` |
| 金标准声明无证据率 | `0/10`，`0%` | 不高于 `10%` |

路径指标使用冻结案例的语义节点名。实现内部第二轮检索会再次进入 `plan_research` 选择下一个冻结调用，但 v1 语义路径只记录首次研究规划；成功的 `assess_evidence` 记作 `synthesize-evidence`，失败评估仍记作 `assess-evidence`。此映射固定在运行器代码中，不读取预期路径来生成实际路径。

边界：

- `0/10` 只表示 10 条实际报告声明全部精确匹配冻结金标准并绑定引用；不等于真实模型事实正确率。
- `10/10` 引用指标只统计实际生成报告中的 10 个引用，不把无报告案例算入分母。
- 运行器只使用系统临时目录保存 checkpoint 和测试制品；JSON 基线不保存路径、密钥或完整供应商响应。
- 运行器不使用 `expected` 路径、终态、尝试上限或必需证据去驱动图执行，避免把预期答案复制成实际结果。
- 本阶段没有真实模型、真实资料、token、费用或人工质量量表结果。
