# P2 V2 产品需求

- 版本：`p2-v2-prd-0.1`；日期：2026-09-13；状态：提案，待设计评审。
- 依赖：[审查结论](01-CURRENT-STATE-AUDIT.md)、[技术架构](03-ARCHITECTURE.md)。

## 1. 推荐场景

为准备实现 AI 工作流的学生和小团队生成「有证据、可暂停、可复查的框架选型简报」。首批比较 LangGraph 与 PydanticAI；候选只是研究对象，P2 本身继续使用 LangGraph，不安装另一套框架。

实际问题示例：一个两人团队要做带工具调用、人工审批和失败恢复的研究助手，只能本地运行，维护经验有限。应采用哪种框架？哪些需求由框架原生支持，哪些需要额外基础设施，哪些只能通过 PoC 确认？

这是推荐假设，不是已经完成的用户访谈。首次评审由学习者补一条自己真正面临的决策及约束，作为开发集中的真实任务；不编造需求调研、节省时间或用户收益数据。

## 2. 用户与新增价值

主要用户是做技术决策的开发者；报告供同学、团队负责人或面试官检查。每次解决一个问题，不承诺广泛行业研究。

相对 V1 新增：

- 使用真实官方资料；展示来源版本、采集日期和可定位章节。
- 接收新的需求与约束，模型提出受控检索调用，不能从 case ID 取固定答案。
- 对所有候选使用相同维度；区分「有支持」「有反证」「未找到证据」，不能把未知写成不支持。
- 给出条件推荐、不可行原因或不足以推荐的结论，并列出验证步骤。
- 用户可真正发起、查看、审批、退回、关闭进程后恢复；不再依赖预设人工动作。
- 记录真实模型调用、token、成本估计/未知费用及失败；分开展示工程可靠性与内容质量。

P1 聚焦知识库问答；P2 的差异是需求审批、跨候选证据覆盖、有限补检索、报告修改和恢复。首版无需调用 P1 或 P3。

## 3. MVP 输入与输出

输入为本地 JSON 需求文件，通过 CLI 校验和展示：

- 决策问题、读者、2 个候选 ID、3～5 个维度。
- 硬约束及其优先级：例如本地运行、必须人工审批；与偏好分开。
- 可选维度权重，总和 100；首个闭环只输出证据矩阵，不伪造精确分数。
- 批准的资料 snapshot ID、资料截至日期、目标产品版本或「文档访问日期版本」。
- 模型配置指纹、调用/费用上限和「不确定结论」许可。

首个闭环固定 2 个候选、3 个维度：结构化结果与工具调用、人工审批、持久化/恢复。不能把框架本体能力与附加持久化服务混为一项；每个事实标明组件与配置前提。

输出为结构化报告及其 Markdown：需求复述、两候选同维度矩阵、原子事实及引用、条件推荐/暂不推荐、冲突和缺口、风险、3 条以内 PoC 验证建议、来源列表及运行摘要。摘要约 150～250 中文字，正文目标 800～1500 字，不为了字数补猜。

数据与审校允许保存内部草稿；只有最终人工批准才能创建最终制品。暂不推荐的简报可以完成交付，但必须标记 `decision_status=insufficient_evidence`，不能计为成功推荐。

## 4. 用户流程

1. 用户填写实际需求，CLI 展示缺失项；无模型调用即进入第一次人工确认。
2. 批准范围、资料、模型配置和本次预算后，程序按已冻结快照执行研究。
3. 模型提出检索/读取调用；代码校验并执行。模型整理证据，程序检查每个候选×维度是否有依据或显式缺口。
4. 最多补检索一次。硬约束仍未知、矛盾未解决或无法比较时，停止推荐，写有限简报；完全无可核验证据则失败，不写正文。
5. 模型起草；代码验证结构与引用，模型检查证据与措辞，最多自动修改一次。
6. 用户看到报告、证据、警告与实际用量，批准/退回/拒绝/取消。退回最多一次，每次重新审校和批准。
7. 程序幂等导出。关闭进程后用同一运行 ID 恢复；旧批准不可复用。

首个闭环没有搜索服务或网页抓取步骤；真实资料先单独采集并冻结。刷新资料生成新 snapshot，不改变进行中的研究。

## 5. 产品验收

| 编号 | 条件 |
|---|---|
| P-01 | 无案例 ID 的合法新需求可以发起研究；缺候选/维度先暂停；批准前模型调用数 0 |
| P-02 | 两候选×三维度的全部 6 个单元格均有证据状态，未知不可填成否定或零分 |
| P-03 | 每条可外部核验的事实声明有已读证据定位；引用身份有效率 100%；语义支持率另测 |
| P-04 | 同一输入在脚本模型下可复现全部状态；真实模型不要求文字逐字相同 |
| P-05 | 两个人工门跨进程恢复；错 run/revision/hash/预算配置的批准拒绝；未批准最终导出 0 次 |
| P-06 | 已批准制品重复恢复只有一个最终文件；冲突不覆盖；来源更新不会改变旧报告 |
| P-07 | 超预算、未知计费、模型非法结果、资料损坏、工具越界有稳定结果，无无限循环 |
| P-08 | 保存真实模型基线、独立人工评分、失败样本和成本；门槛见评估方案，不套用 V1 4.8/5 |
| P-09 | 用户能在本机用文档完成发起、审批、恢复、导出；演示标注 offline/live/replay |

有用性验证：邀请学习者和至少一名同学各提交一条真实决策，检查报告能否帮助排除方案或确定下一步实验。没有真实用户参与时，明确记录「有用性尚未验证」，不计为完成证据。

## 6. 暂不做

- 任意联网搜索、递归爬取、新闻、定价排名、私有仓库或上传秘密资料。
- 自动修改项目、运行报告建议的命令、安装候选框架、采购或部署。
- 多智能体、MCP 联动、向量数据库、Embedding、长期用户记忆。
- 账户、多人协作、并发任务、队列、云端托管、Docker 和公开发布。
- 默认本地大模型下载。预算为零时只做离线开发，不能把脚本模型标为真实模型。

## 7. 不做的代价

固定语料只能回答已覆盖主题；新候选要先扩充资料。官方描述不能证明实际性能或稳定性；相关结论保留为待实验项。CLI 不如 Web 易展示，但可先验证真实流程，避免把时间花在尚无内容质量依据的界面上。
