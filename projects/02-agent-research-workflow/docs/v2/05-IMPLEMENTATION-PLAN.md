## 开发任务顺序与学习者参与

以下为原始学习参与建议；用户随后明确委托助手实现与复核，已按小阶段推进。独立练习留作学习验收，不将助手交付认定为学生独立实现：

1. 学习者写一条真实需求，划分硬约束/偏好/资料缺口；助手审查，形成输入例子。
2. 学习者画正常、证据不足、人工退回三条路径；助手检查状态与停止条件，再落合同。
3. 学习者实现或解释一个来源检索/读取核心函数；用真实章节验证输出，不写固定 evidence ID。
4. 学习者写模型结果解析与错误分类；助手提供失败样例，检查「JSON 合法但业务越界」。
5. 学习者实现一次人工批准绑定和恢复测试；助手审查重复请求与费用窗口。
6. 闭环可运行后，由学习者给真实报告打分、记录一个失败原因，再进行单项改进和同集回归。

每步更新 STATUS 唯一目标；需求或技术方向变化写 DECISIONS。学习证据记录实际贡献，不把审阅助手代码等同于独立实现。

## 依赖策略

现有 Python 3.14 项目本地 `.venv`、Pydantic、LangGraph、SQLite、标准库与现存 httpx 足以设计首个闭环。先使用 Markdown 语料，无浏览器、向量库、额外 Agent 框架。

如直接使用 httpx，将 `httpx==0.28.1` 写入直接依赖；变更 pyproject/requirements 输入与完整锁文件保持一致。安装前核对 wheels、Python 兼容、传递依赖、许可、空间和费用，获得批准后执行；不能把 P2 历史安装授权或 P1 环境额度视为本轮安装授权。

LangGraph 补丁升级应独立小任务：审查 1.2.9 到候选版本 release diff、安全公告，先备份 P2 测试用 checkpoint，重跑 V1 与 V2，确认失败恢复；不混入模型行为变更。

## 暂缓及触发条件

- 本地 Web UI：只有 CLI 被真实用户试用且内容门槛达标后再评估；优先展示证据、审批和运行恢复。
- 关键词检索不足：先记录检索遗漏与查询/分段改进；仍不足才对比 BM25/向量方案及新增成本。
- 多智能体：只有同集质量和成本证明单图瓶颈后提案。
- 云部署/服务化：用户明确需要远程访问时再设计认证、并发、数据库和预算，不继承 P1 的资源或验证结论。

## 阶段退出原则

测试失败先定位原因，修复后只跑相关测试再完整必要回归。禁止修改 gold 迎合输出。资料范围、模型、预算扩大必须重新确认。未达到统一 `docs/PROJECT_STANDARDS.md` 与 V2 内容门槛时，状态保持进行中；能跑一份报告不等于项目完成。
