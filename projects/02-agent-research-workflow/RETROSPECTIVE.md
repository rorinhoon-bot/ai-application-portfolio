# P2 开发复盘

- 日期：2026-08-01
- 范围：原创离线 `workflow-v1`
- 当前状态：离线首版和 `LLH_Study.md` 已完成；最终验收审计进行中，因此 P2 仍为 `in_progress`

## 1. 项目结果

P2 把“AI 应用技术选型研究报告”实现为显式 LangGraph 单工作流。流程覆盖需求确认、受控工具执行、证据门、结构化草稿、有限审校、最终人工确认和幂等 Markdown 导出。

当前可核验结果：

- 12 个冻结 `workflow-v1` 案例全部通过。
- 固定路径正确率 `12/12`，引用绑定有效率 `10/10`。
- 重试和停止边界正确率 `12/12`，checkpoint 恢复一致率 `1/1`。
- 实际报告声明无证据率 `0/10`。
- 未批准导出 `0`，提示注入扩大权限 `0`，单案例最终制品最多 `1`。
- 144 个普通测试离线通过；普通测试默认阻断网络。
- 两个人工暂停点、revision/hash 绑定、SQLite 恢复和崩溃窗口重放均有测试。
- 演示 manifest、Markdown 报告、运行摘要和两张 SVG 可确定性重建并逐字节检查。

这些结果证明原创固定夹具下的工作流可靠性，不证明真实模型语义质量、现实资料正确性、实时性或真实调用成本。

## 2. 开发路径

项目按风险边界拆成 12 个独立阶段提交：

1. 固定 PRD、架构、依赖和原创评估资料。
2. 实现最小运行状态和需求确认暂停。
3. 实现严格 Tool Calling 合同、作用域校验和有限重试。
4. 实现两轮证据充分性判断和停止条件。
5. 实现结构化草稿与程序绑定引用。
6. 实现最多两次自动修改的审校循环。
7. 实现最终报告暂停、人工返修及 revision/hash 绑定。
8. 实现不可覆盖、可重放的 Markdown 导出。
9. 用统一运行器执行 12 个冻结案例并保存基线。
10. 加入不扩大 checkpoint 的运行时可观测性。
11. 固定三条代表路径的离线演示。
12. 生成可逐字节验证的展示图和五分钟讲解材料。

小步提交让每阶段只有一个主要失败面。例如，导出阶段不同时修改审校逻辑；可观测性阶段不改变业务状态。这降低了定位回归的难度。

## 3. 最难的问题

### 3.1 人工暂停不是普通函数等待

LangGraph 从 `interrupt()` 恢复时会从中断节点开头重新执行。若节点在暂停前执行不可重复副作用，恢复可能重复操作；若人工决定只绑定当前文本，也可能批准过期状态。

当前方案：

- 暂停节点前先持久化明确的等待状态。
- 需求决定绑定 `run_id`、`thread_id`、需求 revision 和请求哈希。
- 报告决定再绑定报告确认 revision、报告 revision 和内容哈希。
- 人工编辑或返修后增加 revision，并使旧批准失效。
- 最终导出与批准节点分离，批准本身不写文件。

### 3.2 checkpoint 既要足够恢复，又不能保存运行时对象

恢复需要保存业务事实，但连接、客户端、执行器和完整响应会扩大攻击面，也无法稳定序列化。

当前只持久化版本化业务状态：身份、路由、严格需求、计数、证据 ID、安全错误、报告 revision/hash 和制品绑定。SQLite 连接、checkpointer、工具执行器、写作者、审校器、observer、clock、文件句柄、API Key、鉴权头、Cookie 和完整供应商响应均不进入 checkpoint。

### 3.3 幂等导出必须覆盖“文件已写，checkpoint 未提交”窗口

只在状态里标记“已导出”不够。进程可能在文件发布后、checkpoint 成功前崩溃。恢复后节点会再次执行。

当前使用内容寻址 `artifact_id`、固定文件名和不可覆盖的原子硬链接发布：

- 同 ID、同字节返回 `UNCHANGED`。
- 同 ID、不同字节返回 `export-artifact-conflict`，不覆盖旧文件。
- 恢复案例真实制造崩溃窗口；重放后仍只有一个制品。

### 3.4 评估运行器不能偷看预期答案

若运行器用案例中的 `expected_path`、终态或必需证据驱动图执行，`12/12` 只是在复制答案。

当前运行器先仅依据输入、假工具脚本、预设人工动作和独立 gold 规则执行真实图；执行完成后才比较 `expected`。比例指标保存 numerator、denominator 和 basis points，避免只给百分比而无法审计。

## 4. 已验证的失败根因与修正

### 恢复后尝试次数可能错位

- 根因：若假工具或修改器依赖内存游标，进程重开后游标归零，可能重复旧错误或跳过应有步骤。
- 修正：`tool_attempts`、`retrieval_rounds`、`review_rounds` 和 `human_revision_count` 全部持久化；假执行器按状态中的 attempt/round 选择脚本结果。

### 输入合法不代表调用已获授权

- 根因：Schema 只能证明结构合法，不能证明候选、来源、章节、维度或权重属于本次人工确认范围。
- 修正：执行前增加业务作用域和 allowlist 校验。越界调用不进入底层执行器，也不把结果写入状态。

### 弱证据容易被写成强结论

- 根因：只要检索到“相关内容”就写报告，会把相近证据、缺失证据或不可比较数据误当成支持。
- 修正：`evidence-policy-v1` 要求明确 evidence ID 组合；两轮后仍不足以 `evidence-insufficient` 稳定失败，不生成报告。

### 覆盖式写入破坏并发安全

- 根因：临时文件加覆盖式 replace 虽能保持单次原子性，但竞争窗口中仍可能覆盖后来出现的同名文件。
- 修正：最终发布使用“目标不存在才成功”的硬链接；冲突安全失败，不降级覆盖。

### 可观测性容易泄露业务载荷

- 根因：直接记录节点输入输出、完整异常或响应，会把报告正文、路径、密钥形态文本带入日志。
- 修正：observer 仅记录节点、状态变化、稳定错误码、计数和内容哈希；事件属于运行时旁路，不进入 checkpoint。

### 虚拟环境磁盘估算偏低

- 根因：最初按压缩 wheel 大小估算，忽略安装展开和 `.pyc`。
- 修正：实测 `.venv` 为 62.66 MiB，把稳态边界从 50 MiB 修正为 65 MiB，并删除临时 wheelhouse。

## 5. 做得好的地方

- 先冻结来源快照、案例和金标准，再实现工作流；未根据基线结果回改 `workflow-v1`。
- 单工作流已经足够展示状态、分支、循环和人工边界，没有为了使用术语而加入多智能体。
- 所有自动循环都有硬上限；等待人工被建模为正常 `NEEDS_HUMAN`，不是错误。
- 模型潜在权限被限制为三个只读或纯计算工具；最终导出不是模型工具。
- 引用元数据由程序从已验证来源目录绑定，不信任写作者提供的标题、路径或哈希。
- 失败使用稳定错误码和安全摘要；原始异常和完整响应不持久化。
- 评估同时覆盖成功、失败、人工介入、恢复和重复副作用，不只展示一条成功路径。
- README、架构、决策、评估、演示和 SVG 与代码结果保持一致，可离线复核。

## 6. 关键取舍

### 单工作流，而不是多智能体

收益是状态和权限边界清楚、测试成本低、恢复更容易解释。代价是没有比较多智能体对内容质量的增益。当前没有证据支持增加多智能体复杂度。

### 原创固定资料，而不是真实官方资料

收益是离线、无费用、无许可和网页漂移干扰，能准确测试失败路径。代价是报告不能用于现实选型，也不能证明开放检索能力。

### 精确 gold 匹配，而不是模型语义评分

收益是确定性、可审计、无模型评估费用。代价是只能验证固定声明、引用和路由，不能评价任意表达、比较公平性或真实报告可读性。

### 安全失败，而不是尽量完成

证据不足、路径能力不足、硬链接不支持或制品冲突时，系统选择停止。代价是可用性更保守；收益是不靠猜测、覆盖写入或权限降级制造“成功”。

### 运行时 observer，而不是把事件写入业务状态

收益是 checkpoint 更小、更少敏感数据、业务恢复不依赖观测系统。代价是进程崩溃前未外送的事件不能恢复。

## 7. 当前限制

- 没有真实模型、真实 Embedding、真实检索器或开放网页搜索。
- 假写作者、审校器和人工动作是确定性夹具，不代表真实人的判断质量。
- PRD 中“系统可提出候选或维度”尚未实现；当前缺少这些信息时直接暂停，不自行猜测。
- 没有执行 PRD 计划中的人工报告质量量表，因此不能声称平均分达到 `4/5`。
- token、模型调用和已知费用为 `0`，只代表没有调用模型，不是未来成本预测。
- `observed_node_duration_ns` 不含人工等待；固定时钟结果不是性能基准。
- 硬链接发布依赖目标文件系统能力；不支持时会安全失败。
- SVG 字体由查看器选择；保证内容和坐标稳定，不保证跨平台像素一致。
- 未验证 macOS、Linux、并发多进程负载或 SQLite 高并发恢复。
- 没有公开部署、交互 Web UI、真实用户研究或生产监控。

## 8. 真实模型接入条件

真实模型不是当前离线实现的直接替换。开始前必须满足：

1. 明确批准模型供应商、模型 ID、最大调用次数、token 上限、人民币费用预算和超时/重试策略。
2. 提交真实官方资料清单：URL、版本或 commit、许可、文件数、预计大小、保存位置、Content-Type 和 SHA-256 校验。
3. 新增依赖前记录精确版本、用途、Python 3.14 兼容性、许可和磁盘影响。
4. 模型适配器只能输出现有版本化提案合同；URL、路径、命令和工具参数仍需程序校验。
5. API Key 只从环境变量读取；Prompt、完整响应、鉴权头和供应商敏感字段不进入 checkpoint 或提交制品。
6. 两个人工暂停点、循环上限、不可覆盖导出和严格 msgpack 不得因接入模型而放宽。
7. 新建真实资料和真实模型评估版本，保留原创 `workflow-v1` 与首个基线不变。
8. 使用同一离线回归后，再单独报告语义质量、失败分类、token、费用和真实耗时。
9. LangSmith tracing 或其他外部观测默认关闭；启用前另审数据边界和费用。

## 9. 如果重做一次

- 更早画出“业务状态、运行时依赖、敏感数据、观察事件”四类边界，减少后续状态字段调整。
- 在第一个完整成功路径出现时就建立统一评估运行器，避免后期再统一内部节点与外部语义路径。
- 从第一版合同开始同时定义 revision 语义、内容哈希范围和人工决定绑定，减少需求暂停与报告暂停之间的重复设计。
- 在导出设计阶段先列出崩溃窗口和竞争窗口，再选择发布原语。
- 把人工质量量表夹具和真实模型费用合同作为独立未来版本设计，不在确定性基线里预留含糊数字。

## 10. 能向面试官解释的内容

- 为什么 LangGraph 状态图比一次聊天调用更适合长流程研究任务。
- 为什么 `interrupt()` 节点必须考虑重放，批准必须绑定 revision/hash。
- 为什么 Schema 校验之后仍要做业务权限校验。
- 为什么 checkpoint 只保存业务状态，不保存客户端、连接和完整响应。
- 为什么证据不足要稳定停止，而不是让模型补齐。
- 如何测试“文件已发布、checkpoint 未提交”的崩溃窗口。
- 如何防止评估运行器读取预期答案驱动实际结果。
- 为什么当前 `12/12` 不能被描述为真实模型质量 `100%`。
- 为什么首版不用多智能体，以及何时才值得比较多智能体版本。
