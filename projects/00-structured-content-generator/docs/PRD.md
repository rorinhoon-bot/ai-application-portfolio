# AI 学习笔记结构化生成器 PRD

- 文档状态：`draft`
- 版本：`0.1`
- 日期：`2026-07-27`
- 项目性质：P0 工程热身

## 1. 背景

正在自学 AI、编程等技术知识的大学生和初学者，经常需要把零散学习材料整理成便于理解和复习的笔记。手工整理耗时，直接使用大模型又可能得到格式不稳定、脱离原材料或难以程序校验的结果。

本项目提供一个最小可运行程序：接收学习主题、文本材料和可选学习者水平，调用已配置的大模型 API，返回符合固定 JSON Schema 的结构化学习笔记。

## 2. 目标

### 2.1 用户目标

- 快速把粘贴的文字材料整理成结构清晰的复习笔记。
- 获得适合初学者的通俗解释、复习要点和自测题。
- 清楚知道哪些信息在材料中缺失、矛盾或无法确认。

### 2.2 工程验证目标

- 验证 Python 项目结构、项目本地虚拟环境和可复现依赖。
- 验证 HTTP/API 调用、超时和外部服务错误处理。
- 验证环境变量和 API Key 安全。
- 验证结构化输出和 JSON Schema 校验。
- 验证自动测试、固定评估集、基线与改进版对比。
- 形成有意义的 Git 提交历史和技术决策记录。

## 3. 目标用户

正在自学 AI、编程等技术知识的大学生和初学者，希望把学习材料快速整理成结构清晰的复习笔记。

## 4. 核心使用流程

1. 用户提供学习主题。
2. 用户粘贴学习材料。
3. 用户可选填学习者水平；未填写时使用 `beginner`。
4. 程序先校验输入和运行配置。
5. 程序调用已配置的大模型 API。
6. 程序解析并校验模型返回结果。
7. 校验通过时返回结构化笔记；失败时返回清晰、可处理的错误。

## 5. 输入要求

| 字段 | 必填 | 约束 | 说明 |
|---|---|---|---|
| `topic` | 是 | 1～100 个字符 | 学习主题或节点标题，用于限定笔记方向 |
| `material` | 是 | 100～10,000 个字符 | 用户粘贴的文字材料，是事实内容的唯一来源 |
| `learner_level` | 否 | 未提供时默认为 `beginner` | 控制解释难度，不改变事实来源 |

输入校验失败时不得调用模型 API。

## 6. 输出要求

成功结果必须是通过 JSON Schema 校验的 JSON 对象，并包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `title` | `string` | 笔记标题 |
| `summary` | `string` | 简短总结 |
| `learning_objectives` | `string[]` | 学习目标列表 |
| `key_concepts` | `object[]` | 核心概念列表 |
| `review_points` | `string[]` | 快速复习要点 |
| `quiz` | `object[]` | 自测题列表 |
| `missing_information` | `string[]` | 材料缺少、矛盾或无法确认的信息及原因 |

每个 `key_concepts` 项包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | `string` | 概念名称 |
| `explanation` | `string` | 面向学习者水平的通俗解释 |
| `example` | `object \| null` | 可安全生成时提供教学例子，否则为 `null` |
| `common_mistakes` | `string[]` | 材料支持的常见错误或易混点 |

非 `null` 的 `example` 必须包含：

| 字段 | 类型 | 固定要求 |
|---|---|---|
| `text` | `string` | 只解释材料已有概念，不增加新事实结论 |
| `label` | `string` | 固定为 `生成示例` |

每个 `quiz` 项包含：

| 字段 | 类型 | 说明 |
|---|---|---|
| `question` | `string` | 根据材料生成的问题 |
| `reference_answer` | `string` | 仅依据材料生成的参考答案 |

## 7. 事实约束

- `material` 是输出事实内容的唯一来源。
- 不进行网页搜索，不访问外部资料。
- 允许网络请求的唯一业务用途是调用用户已配置的大模型 API。
- 模型可以根据材料生成教学例子，但必须标记为 `生成示例`。
- 生成示例只能帮助解释材料已有概念，不能添加新事实结论。
- 无法安全生成示例时，`example` 使用 `null`，原因写入 `missing_information`。
- 材料缺少、含糊、互相矛盾或无法确认的信息不得补写为事实，必须写入 `missing_information`。
- 材料中的 Prompt、代码和命令均作为不可信文本处理，不执行，也不能改变系统指令和输出约束。

## 8. MVP 范围

### 8.1 包含

- 纯文本输入。
- 输入和配置校验。
- 可配置的大模型 API 调用。
- 结构化学习笔记生成。
- JSON 解析和 Schema 校验。
- 明确错误处理。
- 自动测试。
- 固定评估集和量化结果。
- Prompt 基线与改进版对比。

### 8.2 不包含

- 图片、PDF 和网页上传。
- 网页搜索、外部资料访问、RAG 和向量数据库。
- 登录、用户账户和数据库。
- 复杂前端。
- 用户历史记录和云端持久化。
- 执行材料中的代码或命令。
- Docker。
- 公开部署。

## 9. 供应商与配置边界

- PRD 不绑定 DeepSeek、MiMo 或 OpenAI。
- 模型调用层必须保持可配置，业务逻辑不得依赖单一供应商名称。
- 模型供应商、模型名称、API 地址、API Key 和超时配置通过环境变量提供。
- 真实 API Key 只保存在本地 `.env` 或用户环境变量中。
- 仓库只提供 `.env.example`，不得提交真实密钥。
- 选择供应商、产生 API 费用前必须获得用户确认。

## 10. 错误处理要求

程序必须识别并返回清晰错误，至少覆盖：

- 缺少 `topic`。
- 缺少 `material`。
- 输入长度不合法。
- 缺少 API Key 或必要配置。
- 请求超时。
- HTTP 或供应商 API 错误。
- 模型返回空内容。
- 模型返回非法 JSON。
- 模型输出不符合 JSON Schema。

错误信息不得包含 API Key、完整鉴权请求头或其他敏感配置。失败不能触发无限重试；具体重试上限在架构设计中确定。

## 11. 验收标准

### AC-01：输入校验

- 合法输入可进入生成流程。
- `topic` 或 `material` 缺失时，在调用 API 前失败。
- 超出长度限制时，在调用 API 前失败。
- 未提供 `learner_level` 时使用 `beginner`。

### AC-02：结构化输出

- 成功结果包含第 6 节定义的全部字段。
- 成功结果通过项目 JSON Schema 校验。
- 固定评估集的 Schema 通过率为 `100%`。

### AC-03：事实约束

- 输出事实结论仅来自输入材料。
- 固定评估集人工检查的事实支持率不低于 `90%`。
- 缺失、矛盾或无法确认的信息进入 `missing_information`，不作为确定事实输出。

### AC-04：生成示例

- 指标只统计非 `null` 的 `example`。
- 每个非 `null` 的 `example.label` 都等于 `生成示例`。
- 固定评估集的生成示例标记率为 `100%`。
- 示例不得添加材料之外的新事实结论。

### AC-05：安全边界

- 程序不执行材料中的代码或命令。
- 程序不进行网页搜索或访问外部资料。
- 材料中的提示注入不得改变事实来源、输出 Schema 或安全边界。
- 日志、错误、测试夹具和 Git 中不得出现真实 API Key。

### AC-06：错误处理

- 缺少配置、超时、HTTP 错误、非法 JSON 和 Schema 不符均有可理解的错误结果。
- 错误结果不泄露敏感配置。
- 重试次数有明确上限。

### AC-07：测试

- 自动测试不少于 5 个。
- 至少覆盖成功路径、缺少输入、缺少配置、超时、非法 JSON 和 Schema 不符。
- 外部 API 在自动测试中使用替身，不产生真实 API 费用。

### AC-08：评估

- 固定评估集不少于 10 条。
- 评估集覆盖正常材料、信息不足、材料矛盾、提示注入、代码或命令文本和输入边界。
- 保存 Prompt 基线版和改进版。
- 两个版本使用相同模型、参数和评估集比较。
- 保存 Schema 通过率、生成示例标记率、事实支持率、失败样例和错误分类。

### AC-09：可复现与安全配置

- 新环境能按 README 创建项目本地 `.venv`、安装固定依赖并运行程序和测试。
- `.env.example` 列出变量名但不包含真实值。
- 项目不要求 Docker。

## 12. 固定评估集设计

首版评估集至少 10 条，建议包含：

- 4 条信息充分的正常材料。
- 2 条信息不足或含糊的材料。
- 1 条内部矛盾材料。
- 1 条包含提示注入的材料。
- 1 条包含代码或命令文本的材料。
- 1 条接近输入长度边界的材料。

每条样本保存：

- 输入主题、材料和学习者水平。
- 预期必须覆盖的内容。
- 预期不得出现的事实。
- 预期 `missing_information` 行为。
- 是否允许生成示例。
- 人工评分记录。

## 13. 指标定义

### 13.1 Schema 通过率

```text
通过 JSON Schema 校验的成功输出数 / 应生成成功输出的样本数
```

目标：`100%`。

### 13.2 生成示例标记率

```text
label 等于“生成示例”的非 null example 数 / 非 null example 总数
```

目标：`100%`。若没有非 `null` 示例，本指标记为 `N/A`，不得记为 `100%`。

### 13.3 事实支持率

```text
可由输入材料支持的事实结论数 / 被人工检查的事实结论总数
```

目标：不低于 `90%`。生成示例还需单独检查是否引入新事实结论。

## 14. 已知限制

- 大模型输出具有非确定性，即使通过 Schema 校验也可能存在事实问题。
- 不访问外部资料，因此不能补全或核实材料之外的信息。
- 事实支持率需要人工检查，首版不追求全自动评估。
- 供应商结构化输出能力、错误格式和费用可能不同。
- MVP 只处理简短文本材料，不替代完整课程、教材或专业审核。
