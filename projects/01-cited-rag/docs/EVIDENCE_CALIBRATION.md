# 证据充分性与拒答校准

- 状态：`blocked-on-design-choice`
- 版本：`0.1`
- 日期：`2026-07-29`

## 1. 目标

检索返回5条结果不等于证据足够。拒答规则至少要同时做到：

- 语料能回答时，不能大量误拒。
- 语料不能回答时，不能因为“主题相似”就编造答案。

本阶段不调用MiMo。先验证只用Qdrant Cosine分数能否可靠决定拒答。

## 2. 独立校准集

文件：`data/evaluation/evidence-calibration-v1.json`

- 24题。
- 12题可由当前语料回答。
- 12题应拒答。
- 应拒答题覆盖缺少页面、第三方库、其他语言、无意义问题和提示注入。
- 不复用15题Recall@5集合。

分数定义：

```text
一次检索返回结果中的最大 Cosine 分数
```

候选规则：

```text
最大分数 >= threshold => sufficient
否则 => insufficient
```

自动比较全部相邻分数的中点。要求可回答召回和拒答准确率都不低于80%；并列时优先保留可回答问题。

## 3. 校准结果

报告：`data/evidence-threshold-calibration-report.json`

- 阈值：`0.6187245534246643`
- 可回答召回：100%
- 拒答准确率：91.7%
- 平衡准确率：95.8%

唯一误答是 `asyncio.TaskGroup`。当前语料没有完整TaskGroup API，但Python 3.14新变化片段得到 `0.6286` 的高相似度。

校准结果看似达标，但只能说明规则拟合该校准集，不能当最终证据。

## 4. 锁定评估

文件：`data/evaluation/evidence-evaluation-v1.json`

- 全新20题。
- 10题可回答，10题应拒答。
- 写完后不再调整阈值。

报告：`data/evidence-policy-evaluation-report.json`

- 可回答召回：70%
- 拒答准确率：70%
- 平衡准确率：70%
- 两类均未达到80%。

### 4.1 被误拒的语料内问题

- `range(5)` 不包含5：`0.5788`
- `venv --upgrade-deps`：`0.6100`
- Python 3.13 `Path.walk`：`0.5445`

### 4.2 被误答的语料外问题

- `logging.basicConfig(force=...)`：`0.6557`
- `sqlite3.autocommit`：`0.6281`
- `typing.Protocol(runtime_checkable)`：`0.6373`

这些语料外API在Python 3.14新变化页面可能被零散提及，但没有足够正文回答问题。Cosine分数只反映相似，不证明答案所需事实完整。

## 5. 工程决定

单一分数阈值不能进入生产：

- 不设置默认阈值。
- `EXPERIMENTAL_SCORE_ONLY_POLICY` 只保留复现实验。
- `assess_evidence()` 必须显式传入策略。
- 检索或索引错误继续抛出稳定错误，不伪装成正常拒答。
- 两份评估集和报告保留，不删除失败题。

## 6. 需要选择的下一方向

### 方向A：扩充官方语料

加入 `logging`、`sqlite3`、`typing`、`asyncio` 等官方页面。

优点：来源边界仍简单，更多问题确实可回答。

代价：语料范围、下载清单、Chunk和索引身份全部变化；不能解决所有第三方或任意语料外问题。

### 方向B：增加本地相关性或Reranker组件

使用专门模型判断问题与Chunk是否真正相关，再重新校准。

优点：不把证据判断交给生成模型。

代价：需要选择模型、核实许可与Python兼容性、下载新资产，可能增加延迟和依赖。

### 方向C：进入MiMo结构化证据判断

把检索证据交给MiMo，要求只返回 `answered/refused/conflict`、答案和检索结果中的Chunk ID；程序再验证引用。

优点：能判断“相似片段是否足够回答完整问题”，也与最终回答生成合并。

代价：需要API Key和调用预算；必须用新的独立集验证拒答准确性、忠实度和引用有效率，不能信任模型自报。

## 7. 当前暂停边界

三个方向都会改变已确认范围：A改变语料，B增加模型资产，C开始真实API调用。未获得学习者选择前，不继续实现其中任一方向。
